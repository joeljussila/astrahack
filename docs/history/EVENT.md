# Astra SF — event essentials

## Grading criteria — exact wording

GPT-6 Astra in Development (25%)
How did the team use the model to build their project? Did they leverage new features and capabilities efficiently? How did they work with the model during development?

GPT-6 Astra in Project (25%)
How did the team use GPT-6 Astra in their end project? Does the project incorporate new features to unlock advanced capability? Is the project a novel use of the model?

Live Demo (25%)
Is the concept of this project novel? Is it presented and demo'd well? Is this a cool project to watch? Is this ONLY a demo, and NOT just a presentation, figma file, or anything else?

Technicality (25%)
How well has the team implemented the idea? How technical is their usage and implementation? Is this a project with sound engineering?

## Goal and rules

Build something novel and useful in the real world that makes the best use of Astra's new capabilities. A new startup feature is allowed in an isolated public repository.

- Public repository; maximum four people, solo allowed. All participants need approval.
- Show only features, code, and functionality built during the hackathon. Judges must clearly identify original contributions; failure means disqualification.
- No policy violations or code, data, or assets without usage rights.
- Prohibited: AI mental-health advisors, basic RAG, basic Streamlit apps, image analyzers, education chatbots, job application screeners, nutrition coaches, personality analyzers, medical advice, dashboard-led projects, and sports analyzers/coaches. See the primary guide for exact wording.
